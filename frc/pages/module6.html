程式設計核心：WPILib Command-based

FRC 程式設計的入門票。看完知道：Command-based 是什麼、Subsystem 怎麼寫、PID 與 FeedForward 如何調、PathPlanner / Choreo 差在哪、AdvantageScope 怎麼用。

① WPILib 三大框架對比

FRC 程式有三種寫法，現在 90% 競爭隊伍用 Command-based。其他兩種是歷史。

框架架構適合2026 狀態
TimedRobot類似 Arduino，loop() 每 20ms 執行新手第一週入門、SimpleBot仍可用，KOP 內建
IterativeState machine 寫法—⚠ 已淘汰，不推薦
★ Command-basedSubsystem + Command + Trigger，CommandScheduler 驅動所有競爭隊伍、複雜機構主流；2027 有 Command-based v2

② Subsystem 標準模板（以 Drivetrain 為例）

Command-based 的核心：每個機構是一個 Subsystem，提供 set/get 介面 + default command。

// DriveSubsystem.java — 五個必備區塊
public class DriveSubsystem extends SubsystemBase {
  // 1️⃣ 硬體成員（建構式建立）
  private final TalonFX leftMotor = new TalonFX(1);
  private final TalonFX rightMotor = new TalonFX(2);
  private final DifferentialDrive drive = new DifferentialDrive(leftMotor, rightMotor);

  // 2️⃣ periodic() — 每 20ms 自動執行（更新狀態 / log）
  @Override
  public void periodic() {
    SmartDashboard.putNumber("LeftPos", leftMotor.getPosition().getValue());
  }

  // 3️⃣ 公開方法（讓 Command 操作）
  public void arcadeDrive(double speed, double rotation) {
    drive.arcadeDrive(speed, rotation);
  }

  // 4️⃣ Command Factory — 回傳 Command（取代舊式繼承 Command）
  public Command driveCommand(DoubleSupplier fwd, DoubleSupplier rot) {
    return run(() -> arcadeDrive(fwd.getAsDouble(), rot.getAsDouble()));
  }
}

// 5️⃣ 在 RobotContainer 註冊 default command
drive.setDefaultCommand(drive.driveCommand(controller::getLeftY, controller::getRightX));

💡 關鍵觀念：Subsystem 只「提供能力」，Command 才「決定什麼時候用」。例如 Drivetrain 提供 arcadeDrive() 方法，但是否要驅動由 Command（手動 / 自動 / 預設）決定。

③ PID + FeedForward 調參互動模擬器

P = 回正力 / I = 消除穩態誤差（FRC 多半不用）/ D = 阻尼 / FF = 已知物理（kS、kV、kA）的預測前饋。

④ Path Planning：PathPlanner vs Choreo

自動期（autonomous）的 15 秒，機器人要自己跑完整套路徑。兩大主流工具：

PathPlanner

• GUI 編輯路徑（拖曳路徑點）
• Auto routine：拖拉 Command 組合自動程序
• 較易上手，新手友善
• 2026 主流，PPLib 可讀 Choreo 軌跡
• 文件齊全

Choreo

• 時間最佳化軌跡（SleipnirGroup 引擎）
• 數學求解，跑得比 PathPlanner 快
• Swerve 競爭隊主流（Team 254 公開使用）
• 學習曲線陡
• 可匯出 .traj 給 PPLib 執行

💡 建議：第一年用 PathPlanner，熟悉後切到 Choreo 追求更短的 auto 路徑時間。兩者可混用（PathPlanner 編輯路徑 + Choreo 優化）。

⑤ AprilTag + Vision Pose Estimation

2024 後幾乎所有競爭隊伍標配。AprilTag 是場上貼的 QR-code 風格定位標籤，機器人用相機看到後反推自己在場地的位置。

  1. 相機看到 AprilTag → solvePnP 算相機相對 tag 的姿態
  2. 結合 field layout JSON（2026 有兩套：welded / AndyMark）算 robot pose
  3. 用 SwerveDrivePoseEstimator 結合 odometry + vision，做 Kalman filter 融合
  4. PathPlanner / Choreo auto 程式直接吃融合後的 pose

2026 規格：使用 36h11 tag 家族（誤識別率最低）。建議搭配 PhotonVision MultiTag 在 coprocessor（Orange Pi 5、Raspberry Pi 5）跑視覺處理，減少 roboRIO 負擔。
